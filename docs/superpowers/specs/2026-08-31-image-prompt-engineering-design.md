# Image Prompt Engineering — creator and campaign — Design

**Date:** 2026-08-31
**Status:** Approved for planning
**Scope owner:** `lib/ai/prompts/`, `app/api/studios/creator`, `app/api/studios/campaign`, the three image adapters

---

## 1. Scope

Rebuild the image-generation prompt path for the two studios that never received
the engineering `edit` and `photoshoot` did, and give both a real output canvas.

In scope:

- `lib/ai/prompts/creator.ts` — rewritten
- the campaign route's inline image prompt — moved into a builder
- a new shared photographic-direction module
- a new Arabic-to-brief expansion layer, used by `creator` only
- `aspectRatio` support in the `gpt` and `flux` adapters, and a platform field
  on `creator`

Not in scope:

- `edit.ts` and `photoshoot.ts`. Both are engineered, both were proved against
  real production generations, and neither is changed here.
- the text studios (`plan`, `analysis`, `storyboard`, campaign **copy**).
- the admin prompt-override paths, beyond keeping them working.

## 2. Current state, measured

### 2.1 The two studios are spec sheets, not briefs

| File | Lines | Shape |
|------|-------|-------|
| `lib/ai/prompts/edit.ts` | 847 | 14 presets, per-mode direction, text-containment rule, diacritics rule |
| `lib/ai/prompts/photoshoot.ts` | 576 | `SUBJECT` / `SHOT` / `SET` / `MUST` / `AVOID` / `BRAND`, seeded shot recipes |
| `lib/ai/prompts/creator.ts` | **103** | a bullet list |
| campaign image prompt | **~20, inline in the route** | a bullet list |

`creator` is the first studio in the product, costs 1–4 credits, and is where
every customer starts.

### 2.2 The customer's Arabic reaches the image model raw

There is no translation or expansion anywhere on the path: `router.ts`,
`gemini.ts` and `openai.ts` contain zero occurrences of `translat` or `Arabic`.
`creator.ts:54` emits the customer's sentence verbatim:

```
- Subject: عايز صورة شاورما تجيب جوع
```

The product already knows this is wrong. `lib/ai/prompts/prompt-builder.ts` — the
**free** studio — states the correct rule in its own prompt:

> "The customer describes what they want in Arabic; you return English prompts a
> generative model can act on… 'shot on a 50mm at f/1.8' beats 'beautiful'."

That knowledge is behind a separate, optional studio the customer must visit,
copy from, and paste back. Nothing carries it into the studio that needs it.

### 2.3 Four dead lines in every creator generation

`app/api/studios/creator/route.ts:221-226` never passes `mood` or `platform` —
there are no such fields in `InputSchema`. So `buildCreatorPrompt`'s defaults
ship on every request:

```
- Mood: Professional               fixed, no source
- Platform: General                fixed, no source
- Resolution: 4K                   the model does not read pixel dimensions from prose
- Resolution optimized for general use
```

### 2.4 Style is a bare slug

`components/studios/creator/CreatorForm.tsx:47` offers four values —
`photographic`, `illustrative`, `minimalist`, `bold` — and
`creator.ts:62` emits `- Visual Style: bold`.

This is the defect class CLAUDE.md already records for `plan.ts` ("20+ years of
experience in **the other industry**"): a slug spliced where a sentence belongs.
`photoshoot`'s presets are the counter-example — each names lighting, grade,
composition and material response in full.

### 2.5 Every image is square

`aspectRatio` exists on `ImageGenerationInput` (`router.ts:41`) and only `edit`
passes it. The router's own comment states the constraint:

> "If a text-to-image caller ever passes this, extend the gpt/flux adapters
> FIRST: an aspect ratio that is part of a paid spec being quietly ignored is
> exactly the defect class this file's other comments catalogue."

Adapter reality today:

| Adapter | Parameter | Current behaviour |
|---------|-----------|-------------------|
| gemini | `imageConfig.aspectRatio` + `imageSize` | forwards it; already correct |
| gpt | `size: "WxH"` | `openaiImageSize()` returns `1024x1024` / `1536x1536` / `2048x2048` — always square |
| flux | `width` / `height` | `sizeMap` returns square at all three resolutions |

An Instagram story generated by `campaign` is square. So is a story from
`creator`.

### 2.6 The campaign image prompt is outside the guard

`app/api/studios/campaign/route.ts:400-415` builds its image prompt inline. Its
own comment admits the consequence: `prompt-builder-sanitized` scans
`lib/ai/prompts` only, so this prompt is not covered by the invariant that exists
to cover exactly this.

## 3. Design

### 3.1 Module map

| Module | Status | Purpose |
|--------|--------|---------|
| `lib/ai/prompts/direction.ts` | new | Deterministic photographic direction: style tables, platform framing. No model call. |
| `lib/ai/prompts/visual-brief.ts` | new | The Arabic→brief expansion: prompt, response schema, parser, degradation contract. |
| `lib/ai/prompts/creator.ts` | rewritten | Assembled on `photoshoot`'s shape. |
| `lib/ai/prompts/campaign-image.ts` | new | The campaign route's image prompt, moved under `prompt-builder-sanitized`. |
| `lib/ai/openai.ts`, `lib/ai/replicate.ts`, `lib/ai/models.ts` | extended | `aspectRatio` honoured, not dropped. |

### 3.2 `direction.ts` — deterministic, free, shared

Two closed tables, each entry a full sentence in `photoshoot`'s idiom rather
than a slug.

```
STYLE_DIRECTION: Record<StyleId, {
  camera:      string   // body, lens, aperture
  lighting:    string
  composition: string
  grade:       string
  surface:     string   // material response
}>
```

Keys are exactly the four ids `CreatorForm.tsx:47` offers. The route's
`style` field becomes a `z.enum` built from this table's keys, replacing
`z.string().max(100)` — the same move `storyboard` and `voiceover` already made,
and it turns the set of reachable prompts from bounded into finite.

```
PLATFORM_FRAMING: Record<PlatformId, {
  aspectRatio: string   // the ratio each adapter is asked for
  framing:     string   // stated in prose as well as passed as a parameter
  safeArea:    string
}>
```

`framing` is emitted into the prompt **and** `aspectRatio` is passed to the
adapter. Both, deliberately: the parameter sets the canvas, the prose stops the
model composing a centred square inside a vertical frame.

**The platform set.** `campaign`'s `InputSchema` already closes it to five
(`campaign/route.ts:29`) and that contract is not changed here. `creator` gains
the same five plus a `general` default, so the new field is optional and every
existing client keeps working:

| PlatformId | Ratio | Used by |
|------------|-------|---------|
| `general` | 1:1 | creator default |
| `instagram` | 4:5 | both |
| `tiktok` | 9:16 | both |
| `linkedin` | 1:1 | both |
| `twitter` | 16:9 | both |
| `facebook` | 1:1 | both |

One ratio per platform is lossy — an Instagram feed post and an Instagram story
are different canvases behind one id. Splitting them means changing campaign's
public enum, which is deliberately deferred rather than bundled here.

The exact ratio **strings** each adapter accepts are part of §3.8's open
verification, not assumed. `edit` proves `1:1` and `2:3` against gemini today;
nothing in this repo has yet proved `4:5`, `9:16` or `16:9` against any adapter.

### 3.3 `visual-brief.ts` — the expansion layer

One text-model call, before the credit reservation, constrained by a
`responseSchema` (the mechanism `test:response-schemas` already covers):

```
{ subject, setting, lighting, composition, mood, palette }
```

**Contract:**

- Returns the parsed brief, or `null`. It never throws to the caller.
- `null` on: transport failure, deadline, unparseable output, or any field
  failing the schema. The caller degrades.
- The prompt instructs the model to preserve the customer's intent and to add
  photographic specificity, never to invent subject matter the customer did not
  ask for.

**Security — this is the load-bearing part.** The returned brief is
model-authored text destined for the image model. That is the same class as
`post.scenario`, which the campaign route already treats correctly
(`campaign/route.ts:373-391`). Every field of the parsed brief passes
`sanitizePrompt` **after** expansion, inside the builder, so no future caller can
route around it. A blocked brief degrades to the raw path — it does not fail the
request, because the customer's own sentence already passed the filter.

### 3.4 Order of operations in the creator route

Unchanged in structure; the expansion slots into the existing pre-reservation
block:

```
1. auth, rate limit, validate
2. sanitize the customer's Arabic          (existing, route.ts:162)
3. EXPAND -> visual brief, or null          (new)
4. sanitize the brief's fields              (new, inside the builder)
5. build the prompt                         (existing, route.ts:221)
6. reserveCredits                           (existing, route.ts:262)
7. generateImage
```

`sanitize-before-reserve` stays satisfied. Any expansion failure happens while
the customer has been charged nothing.

### 3.5 Degradation is disclosed

On `null`, the route generates from the improved prompt with the customer's raw
description as `SUBJECT`, and the response carries a flag. The UI states that
Pyra used the description as written.

Precedent: CLAUDE.md records that voiceover's dialect rewrite failing was
"swallowed by a bare `catch {}` returning `enhanced:false` — indistinguishable
from 'nothing to enhance'", and that the fix was to log and disclose. This is the
same shape and takes the same answer.

The brief itself is **not shown to the customer**. It is written into
`generations.input` (JSONB, no migration — the precedent is `promptVersion`) for
diagnosis, and that is all.

### 3.6 The rewritten creator prompt

```
role
SUBJECT           expanded brief, or the raw description when degraded
CLIENT CONTEXT    buildBrandContextBlock(), unchanged
FRAME             camera + composition (STYLE_DIRECTION) + framing (PLATFORM_FRAMING)
SET               lighting + grade + surface
MUST
AVOID             including the Arabic text-containment rule
BRAND             colours as light and accent, never recolouring the subject
```

The four dead lines from §2.3 are removed.

**Text containment.** `creator` today carries one weak line
(`creator.ts:95`: `NO extra text, logos, or watermarks unless specified`).
`edit.ts` earned a real rule over three production runs, and `creator` generates
signage, packaging and menu boards — the exact surfaces where the failure was
observed. `AVOID` states containment in `edit.ts`'s proven idiom.

This is a port of wording that was *measured*, not a rewrite of it. `edit.ts`'s
own header records why: a fixed list of nouns naming surfaces that must stay
blank once named the very surface a preset was aiming at.

### 3.7 Campaign

`post.scenario` is already English and model-authored, so it needs no expansion —
only framing. `campaign-image.ts` takes the scenario as `SUBJECT` and emits the
same `FRAME` / `SET` / `MUST` / `AVOID` blocks, with the platform from the
route's existing `z.enum` driving `PLATFORM_FRAMING`. Moving it out of the route
puts it under `prompt-builder-sanitized`.

Campaign images are pinned to `model: 'gemini'` in the route, so campaign gains
the true canvas immediately.

### 3.8 Adapters

| Adapter | Change |
|---------|--------|
| gemini | none — already correct |
| gpt | `openaiImageSize(resolution, aspectRatio)` returns a size the API accepts for that ratio |
| flux | `sizeMap` becomes a function of resolution **and** ratio, honouring the model's own width/height constraints |

**Two risks to settle before writing the adapter code, both pre-existing and
both currently unverified:**

1. `openaiImageSize()` returns `1536x1536` and `2048x2048`. `gpt-image-2`
   publishes a fixed set of accepted sizes and these may not be in it — in which
   case every 2K/4K `gpt` request already fails today.
2. flux-1.1-pro constrains `width`/`height` to a documented range and step. The
   `4K` entry is `2048x2048` and may already exceed it.

Neither is claimed as a defect here. Both are cheap to settle with one request
per adapter at the smallest size, and the aspect-ratio work has to touch these
exact functions anyway. If either is broken, it is a separate finding and gets
recorded as one.

CLAUDE.md already notes that 4K paths are unmeasured ("business/agency 4K … a
different model id"), which is consistent with both risks.

## 4. Verification

### 4.1 Build gates

| Gate | Change |
|------|--------|
| `test:prompts` | golden strings for both `direction.ts` tables and the rewritten creator/campaign shapes |
| `test:visual-brief` (new) | the parser, the schema, and every degradation path returning `null` rather than throwing |
| `test:response-schemas` | the expansion schema joins the set it already checks |
| `prompt-builder-sanitized` | now covers the campaign image prompt for the first time |
| `sanitize-before-reserve` | already covers the new ordering; no change |
| `studio-error-codes` | any new code registered with copy in both locales |

Each new gate is proved by deliberately introducing the violation it exists to
catch, per this repo's standing rule.

### 4.2 Live verification

Gates cannot show that an image got better. Before this is called done:

- one real `creator` generation per style, `mock: false`, both degraded and
  expanded paths, compared against the same request on today's code;
- one real `campaign` run with images, checking that nine images arrive framed
  for the selected platform;
- one real generation per adapter at each resolution and each ratio, which is
  also what settles §3.8's two risks;
- an Arabic-signage request, checking containment holds the way it does in `edit`.

CLAUDE.md's standing caveat applies: nothing is done until it has been run
against a live model.

---

## 5. What this does not fix

- `edit`'s brand-context wiring is still dead. Out of scope, older than this
  work, and already recorded.
- A studio can still bill for a visual no-op. Recorded as open in CLAUDE.md;
  the honest metric for it does not exist yet and is not invented here.
- The expansion adds one text-model call to every `creator` generation. It is
  not billed to the customer and it is not cached. If latency becomes a
  complaint, caching on `(prompt, style, platform)` is the obvious next step and
  is deliberately not built now.
